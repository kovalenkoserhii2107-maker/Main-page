Аудит закупівель ЄІБ

Рушій, що перевіряє закупівлі Prozorro на стиках між українським законодавством і вимогами Європейського інвестиційного банку. Кожна знахідка має доказ із джерела, а те, що перевірити неможливо, так і позначено — і ніколи не згортається в «порушень немає».

Огляд

Перевірка на швах двох систем правил

Закупівлі за кредитні кошти ЄІБ мусять одночасно відповідати Закону 922-VIII, постанові КМУ № 1178 і правилам банку. Розбіжності між ними — це «шви»: місця, де закупівля може бути законною за одним набором правил і порушувати інший. Рушій перевіряє чотирнадцять таких швів.

Кожен шов повертає один із трьох станів: спрацював, чисто або неможливо перевірити. Третій стан принциповий: якщо в документах немає даних, рушій так і каже, а не зараховує тендер до чистих. Тому звіт показує не лише знахідки, а й реальну межу можливостей перевірки.

Дані тягнуться з публічних API Prozorro: шість вкладок сторінки тендера, канонічна база ЦБД і окремо — договори, бо саме там живуть зміни. Документи .docx, .doc і .pdf розбираються без сторонніх бібліотек.

Можливості

Що вміє рушій

01

14 перевірок-швів

Від локалізації в машинобудуванні й мови документації до санкційного скринінгу ЄС і змін до договору. Кожна повертає «спрацював», «чисто» або «неможливо перевірити».

02

Нормалізація перед правилами

Сирий JSON спершу перетворюється на аудит-об’єкт; рушій правил ніколи не бачить сирих даних, тож зміна формату API ламає одне місце, а не чотирнадцять.

03

Розбір документів без залежностей

Текст витягується з .docx, .doc і .pdf на чистому Python — щоб перевірити, що саме написано в тендерній документації.

04

Відтворюваний аудит у git

API Prozorro не віддає заголовків CORS, тож обчислення винесено в GitHub Actions: щопонеділка корпус перезбирається, а результат комітиться в репозиторій. Кожна версія аудиту — окремий коміт.

05

Звіт на GitHub Pages

Статична сторінка читає готовий датасет: огляд корпусу, калібрування швів із часткою спрацювань лише серед перевірних випадків і реєстр із фільтрами.

06

Точкова перевірка тендера

Для перевірки однієї закупівлі «наживо» є Cloudflare Worker — CORS-проксі, що пропускає запити лише до хостів Prozorro й відкритим проксі не є.

Архітектура

Як це влаштовано

Конвеєр: пошук → вкладки й ЦБД → нормалізація → документи → рушій правил → знахідки. Клієнт Prozorro кешує все на диск, тож повторний прогін не ходить у мережу.

Жодних залежностей — лише стандартна бібліотека Python 3.9+. Окремий скрипт звіряє, що правила в Python і їхня копія для браузера не розійшлися.

  pz.py             клієнт Prozorro: пошук, 6 вкладок, ЦБД, договори; кеш на диску
  normalize.py      сирий JSON → аудит-об’єкт
  docs.py           текст із .docx, .doc, .pdf
  rules.py          14 швів: fires / clear / not_checkable
